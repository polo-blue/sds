# Backward compatibility

`spoko-design-system` is published to npm by semantic-release on every merge to `main`, so any change to a surface below reaches consumers in the next release. Review skills check changes against this file; implementation skills warn when a change is not compliant.

**General rule:** a breaking change to a protected surface ships only with a `BREAKING CHANGE:` commit footer (major version bump) and a migration note — in the PR body and, for non-trivial migrations, a `MIGRATION-*.md` file at the repo root (see the existing `MIGRATION-BREADCRUMBS.md`, `MIGRATION-COLORS.md`). Prefer an additive change plus a deprecation over a removal: keep the old name working for at least one minor release and mark it `@deprecated` in code and docs.

## Protected surfaces

### 1. Root barrel — `index.ts` (`"."` export)

Every named export (Vue/Astro components, utilities, types) is public API.

- **Breaking:** removing or renaming an export; changing what an export points to in an incompatible way; moving a component out of the barrel (including when a `<script>` tag is added to an exported Astro component — required by `CODE_REVIEW.md`, but still breaking).
- **Non-breaking:** adding an export of a component **without** a `<script>` tag.

### 2. Subpath exports (`package.json` → `exports`)

`./components/*`, `./styles/*`, `./styles/tokens.css`, `./scripts/*`, `./scripts/product-gallery`, `./components/Product/product-gallery.css`, `./icons`, `./icon-collections`, `./uno-config`, `./utils/*`, `./astro/*`, `./vue/*`, `./react/*`.

- **Breaking:** removing a subpath; moving or renaming a file reachable through a wildcard subpath (e.g. `src/components/ButtonCopy.astro` → consumers import `spoko-design-system/components/ButtonCopy.astro`); dropping a file from `files`.
- **Non-breaking:** adding a subpath or a new file under an existing wildcard.

### 3. Component props, slots, events and emitted DOM contracts

Props (names, types, defaults), named slots, Vue emits (`update:modelValue`, `input`, `focus`, `blur` …), and the documented `data-*` attributes / element ids that client scripts and consumers hook into (`data-copy-text`, `data-sds-tooltip`, `data-drawer-close`, `#dark-mode-toggle`, `#sidebar`, `.category-sidebar-toggler`, …).

- **Breaking:** removing or renaming a prop, slot, or emit; changing a prop's type or a default in a way that alters existing rendering; removing a hook attribute/id that a shipped script or a documented consumer recipe relies on.
- **Non-breaking:** adding an optional prop with a default that preserves current output; adding ARIA attributes; changing a default only to fix an accessibility defect (call it out in the PR and the changelog).

### 4. UnoCSS configuration — `uno-config/`

`createSdsConfig(customConfig)` and its options, the `theme` export (colours, typography, breakpoints, dimensions, effects, grid, container), every **shortcut name** in `uno-config/theme/shortcuts/`, the peer variants, `generatePalette` / `PaletteInput`, and `generateTokensCSS`.

- **Breaking:** removing or renaming a shortcut, theme colour key, breakpoint, or `createSdsConfig` option; changing a breakpoint value; changing a shortcut so it no longer produces the documented component (layout/structure change).
- **Non-breaking:** adding shortcuts or tokens; visual refinements to a shortcut's colours or spacing that keep its role (still announce them in the PR — consumers see the change).

### 5. Design tokens — `src/styles/tokens.css`

The `--color-*` (and other) custom properties, generated by `pnpm build:tokens`, plus theming hooks such as `--sds-focus-ring` (from #522).

- **Breaking:** removing or renaming a custom property.
- **Non-breaking:** adding properties; value changes that keep the token's meaning.

### 6. Global styles — `src/styles/*`

`main.css`, `base/*`, `content.css`, `sds-tooltip.css` are importable through `./styles/*`; their selectors affect consumer pages.

- **Breaking:** removing a documented global class (`.bg-spoko`, `.bg-vw`, `.display-3`, `.component-preview` …) or a file reachable through the subpath.
- **Requires a PR note:** changes to global element rules (focus, motion, scroll padding, prose tables) — they apply to every consumer page.

### 7. Icon configuration — `icon.config.ts`, `icon-collections.ts`

`iconConfig`, `iconCollections`, `isIconIncluded()`, `getIncludedIcons()`.

- **Breaking:** removing an icon or collection that was listed (consumers' `<Icon name="…" />` and `i-*` classes stop resolving); renaming the helpers.
- **Non-breaking:** adding icons or collections.

### 8. Tooling contract

`engines` (`node >= 22.18.0`, `pnpm >= 10.16.1`) and the `type: "module"` / TypeScript-source distribution (`main: ./index.ts`).

- **Breaking:** raising the minimum Node or pnpm version; shipping compiled output instead of sources (or the reverse); adding a required peer dependency.

## Not protected

The documentation site itself — `src/pages/**`, `src/layouts/**`, `src/config.ts` (sidebar), docs-only components such as `ComponentPreview.vue`, `PaletteConfigurator.vue`, `Header/*` — and `scripts/*` build helpers can change freely, as long as the docs stay accurate.
